# 窗口 B 再交付：服务价值表（情景研究，2026-11-11）

**情景研究**：所有数值都是完全预知 LP 的上限。服务准入按 `2026-11-11_sg_service_eligibility.md`：今天 EV 聚合商能做的是智能充电、可中断负荷（IL）和需求响应（DR）；调频和 V2G 只能作为"VPP 框架开放后"的未来情景。

## 一句话结论

在今天合规的服务里，**智能充电 + 可中断负荷** 每端口每天比不控制省 S$0.51（普通周 0.40，尖峰周 1.38），约合每端口每年 S$186。其中 IL 的待命费贡献 S$0.22，而且只需要少充一点、不需要 V2G。即使完全不改充电计划、只把正在充的负荷报成 IL，也能拿到 S$0.30，和智能充电本身（S$0.34）差不多。未来如果开放调频和 V2G，上限是 S$0.74。

## 关键结果

设置：100 个公共端口，7 天一个 episode；训练期和验证期全部 65 个完整周（58 周普通、7 周尖峰；52 周普通价格、13 周高价）；每周约 950 个 session。V2G 情景中 50% 的 AC session 可以放电。没有削峰电价（新加坡这种情况下没有），削峰只在敏感性里看。表：`tables/services_base_*.csv`、`services_sensitivity.csv`、`services_check.json`；图：`figures/services_saving_sources.png`。

### 2. 普通周和尖峰周（比 S1 省，S$/端口/天）

| 情景 | 普通周（58） | 尖峰周（7） |
| --- | --- | --- |
| S1b 不控制 + IL | 0.268 | 0.552 |
| S2 智能充电 | 0.253 | 1.097 |
| S6 智能充电 + IL | 0.404 | 1.380 |
| S3 + V2G | 0.271 | 1.366 |
| S4a + 调频 | 0.471 | 1.409 |
| S4 V2G + 调频 | 0.603 | 1.826 |

- **IL 在普通周最有用**：普通周电价波动小，智能充电只能省 0.25，IL 的待命费（0.20–0.27）和它差不多大；尖峰周的价值主要来自避开高电价。
- **智能充电会减少 IL 收入**（0.30 → 0.22）：充电被挪到便宜的夜间，而那时可报的负荷少、备用价也低。但两者合起来仍然比单做任何一项都好。
- 本期平均价格：USEP 121.6、调频 18.0、应急备用 A 组 13.1（S$/MWh）。

- **IL 激活时长**：按 2025 年起的规则，激活时长不设上限（EMA 计划改为 30 分钟）。即使要求能补回 2 小时的中断，S6 仍然比 S1 省 0.64。
- **到达 SoC** 对今天的方案影响最大（S6：0.61–0.76）。到达 SoC 越低，要充的电越多、可中断的负荷越多，灵活性也越大。
- V2G 相关参数只影响未来情景。

100 个端口的 IL 量**达不到** 0.1 MW 的直接参与门槛。要么通过售电商或 DR 聚合商参与，要么扩大到约 150–300 个端口。LP 里还没有加入"每个时段要么不报、要么至少 0.1 MW"的约束，这需要整数变量。

## 用了哪些假设

| 项 | 值 | 依据 |
| --- | --- | --- |
| IL 价格 | `reserve_price_CONRESA`（应急备用 A 组），按申报量付费，激活无额外收入 | EMC IL 指南：新注册的用电设施都归入 A 组；EMA 资料页 |
| IL 可报量 | 不超过此刻的充电功率 | 只有正在用的负荷才能中断 |
| IL 激活补偿 | 被中断 0.5 h 后，离开前必须能补回来（敏感性 1 h、2 h） | EMA 计划把激活时长改为 30 分钟；激活后补充电的电费差额没算（激活很少发生） |
| IL 的 0.1 MW 门槛和负荷侧 30% 上限 | 没进 LP，只做事后统计 | EMC IL 指南 |
| 调频 | 只算容量收入；激活电量中性；按 0.1 的比例给电池留余量 | 假设；**未来情景** |
| V2G | 只有 AC session 可以，比例 50%，放电功率 = 充电功率；放电效率 0.92；损耗 0.06 S$/kWh | 假设；**未来情景** |
| 削峰电价 | 基准为 0；敏感性 0.05–0.50 S$/kWh，峰值窗口 15:30–17:30（训练期毛需求最高的 4 个半小时） | 新加坡这种情况下没有这类电价 |
| 到达 SoC | 中档（AC 0.2–0.7、DC 0.1–0.5），低档和高档做敏感性 | 占用数据里没有 SoC，见 `2026-11-11_env_lp.md` |

## 没完成什么

- **需求响应（DR）** 没做：它按"压低市场电价带来的节省"分成付费，需要估计负荷减少对 USEP 的影响。
- IL、调频和 V2G 都还没有接进环境，规则基准和 RL 还不能做这些服务，也还没有对应的 LP 回放检验。
- 0.1 MW 门槛（需要整数变量）和 1,000 端口规模下的服务价值表没跑。
- 主备用（primary reserve，`PRIRESA`）没做：负荷也可以提供，但要求低频继电器在 1 秒内自动跳闸，硬件要求更高。

## 需要用户决定什么

1. 主线定为"智能充电 + IL"，DR 作为扩展，调频和 V2G 作为未来情景。这样定可以吗？
2. 下一步是把 IL 接进环境（RL 的动作里加上 IL 申报量），还是先把 DR 补进 LP？
