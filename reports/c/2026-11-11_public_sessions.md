# 公共充电桩 session 生成器（2026-11-11）

## 一句话结论

生成器只模拟公共充电桩，用 2026-10-26..11-09 的端口占用数据校准，在没参与校准的 2026-09-09..10-24 上和真实数据对比：全岛 session 数量相差 0.3%，占用曲线平均相差 0.6 个百分点，停留时长分布 KS 统计量 ≤ 0.05。车辆侧（电池、SoC、车载充电功率）是假设，数据里没有。

## 数据

- 来源：服务器每 5 分钟采集一次全岛公共充电桩状态（LTA DataMall EVBatch 格式），2026-09-07 → 11-09，17,675 张快照，11,880 个端口（AC 10,220，DC 1,660）。原件和清洗脚本在研究工作区 `datasets/raw/sg_ev/lta_ev_charging_availability_snapshots/`、`datasets/scripts/sg_ev/`。
- 每个端口只有"占用 / 空闲 / 未知"和额定功率，**没有实测功率、电量、SoC**。
- **伪 session** = 一个端口连续"占用"的一段。端口经常在状态之间短暂跳成"未知"（中位 5 分钟，约 97 万次），不超过 60 分钟、前面是占用或空闲的未知段视为通信抖动，沿用前一个状态。处理后 108 万段占用里 97% 是"干净"的（到达和离开都观测到、中间没有采集断档、不超过 48 小时）。
- 5 分钟的占用段（约 6%）多数是单次轮询的抖动，生成器校准时只用 ≥ 10 分钟的段。

## 方法

代码：`src/sg_ev_rl/scenarios/public_charging.py`。

**从数据来的**

| 内容 | 分组 |
| --- | --- |
| 到达率 | 5 区 × AC/DC × 工作日/周末 × 半小时 |
| 停留时长（经验分布重抽样） | AC/DC × 工作日/周末 × 到达小时（样本 < 50 时退回到不分小时） |
| 端口额定功率 | 区 × AC/DC |

**到达模型**：每个端口一次只能停一辆车。端口空闲时，每 5 分钟到达的概率是 h = λ / (1 − 占用率)，λ 是观测到的每端口到达率。除以空闲比例，是为了让仿真的到达数和占用率同时对上数据；直接用 λ 会把落在"正被占用的端口"上的到达丢掉，到达数会偏少。仿真前先跑一天预热，避免第一天凌晨所有端口都是空的。

**假设的（`VehicleAssumptions`）**

| 参数 | 默认值 |
| --- | --- |
| 电池容量 | 50 / 60 / 75 kWh，概率 0.3 / 0.4 / 0.3 |
| 车载交流充电功率 | 7 / 11 kW，概率 0.4 / 0.6；实际功率 = min(桩, 车) |
| 直流接受功率、平均降功率系数 | 100 kW，0.75 |
| 到达 SoC | AC 均匀分布 0.2–0.7；DC 0.1–0.5 |
| 目标 SoC | AC 0.9；DC 0.8 |

**需求电量** = min(（目标 SoC − 到达 SoC）× 电池容量, 实际功率 × 停留时长 [× DC 降功率系数])。因此每个 session 单独看都能充满，AC 长停留的车有较大的调度灵活性，DC 几乎没有。

**接入仿真器**：`to_sessions()` 把 session 映射到半小时时段，只要和某个时段有重叠就算在场；超出仿真时长的 session 在末端截断，电量按剩余时间封顶。

**数据切分**：校准只用 10-26..11-09（10 个工作日、4 个周末日，22.4 万段干净 session），真实场景验证期（09-04..10-25）完全不参与校准。`real_sessions()` 可以直接取验证期的真实伪 session，配同样的车辆假设，用于"合成数据训练 → 真实到达检验"。

## 局限

- **占用不等于在充电**。充满后继续停着的时间也算在停留里，所以 AC 的灵活性可能被高估，电量只是上限意义上的估计。
- 车辆参数是假设，需要在论文里做敏感性分析。最值得做的是到达 SoC 和车载交流功率。
- 多口快充柜可能共享功率，"额定功率"会高估同时充电时的可用功率。
- 只区分工作日和周末。`generate(..., holidays=...)` 可以传入公众假期按周末处理，但还没有内置核实过的假期表。
- 校准窗口只有约两周，假设"EV 行为在一年内基本稳定"，作为论文局限说明。
